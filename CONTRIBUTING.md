# Contributing

Thank you for considering a contribution. This initiative is early; respectful feedback is especially useful.

## Ways to contribute
Issues, ideas, documentation, examples, code, tests, CI, integrations, research, standards comparisons, accessibility, UX, security reviews, and community onboarding are all welcome.

## Before opening a PR
1. Search existing issues and discussions.
2. Explain the problem and who benefits.
3. Keep changes focused and reviewable.
4. Include tests or validation for behavior changes.
5. Update docs and changelog when relevant.
6. Identify assumptions, tradeoffs, and limitations.
7. Never include secrets, credentials, personal data, or private information.

## Pull request expectations
Describe what changed and why, link related issues, include validation results, call out breaking changes/security implications, and use respectful language.

## AI-assisted contributions
AI tools may be used, but contributors remain responsible for submissions. Review generated code and claims, verify citations, test behavior, and disclose substantial AI assistance when material to review. Do not submit unverified generated output as fact.

## Scope
New projects should have a clear problem statement, review of existing solutions, scope boundaries, maintainer, and maintenance plan. See [governance](GOVERNANCE.md).

By contributing, you agree that your contributions are offered under the repository's MIT license unless explicitly stated otherwise.
