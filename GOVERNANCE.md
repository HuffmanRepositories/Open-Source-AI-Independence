# Governance

This repository is currently founder-led and community-open. Governance may evolve as contributors and maintainers join.

## Current responsibilities
The repository owner maintains mission and structure, reviews contributions and security reports, keeps status accurate, explains significant decisions, and seeks community input.

## Decisions
- Routine documentation and maintenance may be handled by maintainers.
- New projects begin as issues or discussions.
- Significant mission, scope, or compatibility changes should receive public discussion.
- Decisions should consider evidence, feedback, maintainability, security, and accessibility.
- When consensus is not possible, maintainers should document rationale.

## Maintainers
Maintainers should demonstrate sustained constructive participation and sound judgment. Roles and permissions should be explicit and reviewed periodically.

## Project independence
Projects may have separate maintainers, licenses, governance, and release schedules. Shared mission does not mean centralized control over every project.

## Conflicts of interest
Disclose relevant conflicts when they affect a decision. Do not misrepresent endorsements or affiliations.

Governance changes should be proposed publicly and documented in a pull request or decision record.
