# Security Policy

## Reporting
Do not publish exploitable details, credentials, private data, or risky proof-of-concept material in a public issue.

Use GitHub's private vulnerability reporting feature if enabled. Otherwise contact the repository owner privately through GitHub. Include a description, affected component, safe reproduction steps, potential impact, and suggested mitigation. Do not include real secrets or personal data.

## Scope
This repository currently contains documentation and community coordination material. As code is added, each project must define supported versions and a security contact.

## Principles
- Least privilege and minimal data collection.
- Treat external content and tool output as untrusted.
- Do not store secrets in source control or logs.
- Document threat models and security limitations.
- Use safe defaults and explicit approval for consequential actions.
- Do not claim a prototype is secure without appropriate review.

We will acknowledge reports as promptly as practical and coordinate disclosure with the reporter.
